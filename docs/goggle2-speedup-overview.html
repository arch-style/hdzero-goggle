HDZero Goggle 2 起動高速化のしくみ

電源から HDZero の映像が出るまでを、純正の約 22 秒から約 6 秒にした方法のまとめ (2026-10-28 時点)

約 22 s純正 9.5.1
5.94 sいまの fork (内部の時計、boot 161)
約 7.5 sスイッチから表示まで (ストップウォッチ)

内部の時計は SoC の RTC が数え始めてからの秒です。スイッチの長押し判定、電源 IC の立ち上げ、パネルが光るまでの分が入らないので、手で測ると 1.5 秒ほど長くなります (内訳は未測定)。

考え方

純正の起動は「念のための待ち」と「遅い読み出し」でできていました。映像に要らない処理を後ろへ回し、待ちを本当に必要な所だけにし、遅いフラッシュの代わりに SD カードから読む。この 3 つが柱です。

やったこと

1. 要らない待ちを消す

USB の準備 (S50usb) の sleep 2、rc.sh の sleep 1 を外しました。Goggle 2 には USB の口がありません。機器の一斉認識 (udev の trigger と settle、2.3 秒) もやめ、必要だった /dev/rtc のリンクだけを作ります。SD の記録の写し (1.2 秒) は映像の後に回しました。

2. I2C の「関門」で待ちを最小にする

HDMI 出力、電池電圧、傾きセンサーがつながる I2C 1 番は、カーネル起動から約 7.6 秒より前に触ると固まり、電源を切るまで戻りません。純正の sleep はこれを避ける役もしていました。そこでアプリを早く起動し、1 番の通信だけを決まった時刻まで待たせます (HDZ_I2C1_NOT_BEFORE)。HDMI 出力と傾きセンサーの初期化は映像の後に回しました。映像に要る受信チップ (2 番) は待たずに使えます。

3. 遅いフラッシュより SD カードから読む

内蔵の NOR フラッシュは毎秒約 5 MB と遅いので、共有ライブラリ 7.1 MB とアプリ本体 3.3 MB をカードから /tmp に写して使います。起動スクリプトの写し (rcS v3) が 2.1 秒ごろにカードを先にマウントし、写しを早く始めます。カードは 64 KB クラスタで作り、マウント時の読み込みを 0.12 秒にしました。

4. 並行して進める

画面の設定 (dispw) を裏で早く始めます。画面のドライバ disp.ko にあった 1 秒の待ちは、100 ms にした写しをカードから読みます。

5. 起動中は CPU を最高クロックに

標準の調速 (ondemand) は 2 秒に 1 回しか負荷を見ないので、起動の多くを 816 MHz で過ごしていました。rcS の写しの先頭で 1104 MHz に固定し、15 秒後に元へ戻します。

6. アプリ側の工夫

アプリを直接起動します (起動スクリプトの連鎖を省く)。受信チップの工場較正値はカードに控えて 2 回目から読み出しを省き、OSD の準備はチューナーの初期化と重ねます。OSD のフォント (BTFL) もカードから読みます。

電源から映像までの流れ

  1. boot0 と u-boot (uboot 区画): メモリを初期化し、カーネルを読んで起動する。
  2. カーネル (boot 区画): ドライバを初期化し、rootfs を読み出し専用でつなぐ。
  3. preinit (rootfs の /pseudo_init と /etc/preinit): /proc や /dev などの基本の場所を作り、区画の名前のリンクを作り、overlay を rootfs の上に重ねて「書けるように見える」ルートにする。
  4. 起動スクリプト rcS: app 区画を /mnt/app につなぎ (更新の確認も)、UDISK をつなぐ。overlay の rcS の写しは、ここで CPU を最高クロックに固定し、SD カードを先につないで写しを始める。
  5. rc.final が S スクリプトを順に実行: 映像ドライバの読み込み (S00mpp)、区画名のリンク (S00part)、SD カードのマウント (S01app)、機器の認識 (S10udev)、ネットワーク (S40network)、USB (S50usb)。overlay の rc.final は、ここでカードの init-exp.sh に「省く、裏に回す」を決めさせる。
  6. rc.sh (app 区画): 画面の設定、ドライバ、録画プロセス、アプリの起動。入口が、カードに rc-exp.sh があればそちらを代わりに実行する。
  7. アプリ: 受信チップを初期化して映像を出す。fork は SD カードから写したものが動く。

どこを書き換えたか

場所中身カードを抜くと
アプリ (fork)ソースをしっかり書き換えた本体。フラッシュには焼いておらず、SD カードから起動純正アプリが動く
app 区画の rc.sh先頭に 7 行の入口だけ純正どおり
app 区画の setting.ini自分の設定 (fork の速さの設定を含む)そのまま使われる
overlay の rc.final入口と、段の区切りの印純正どおり
overlay の rcS入口に加えて、起動中の CPU 最高クロック固定 (15 秒) と SD の早期マウント。これだけはカード無しでも効くクロック固定だけ残る
uboot、boot、rootfs、env、bootlogo、UDISK変更なし (env は試験で一時的に変えたが純正に戻した)—

PhoenixCard で全体を戻した後も、カードのスクリプトが設定、入口、rcS をすべて自動で入れ直せます (2 回起動)。

残りと注意

残る大きな塊は、ブートローダとカーネルの合わせて約 2.6 秒です。カードから自作のブートローダ領域で起動する道は作れましたが (14 回成功)、作り直したカーネルで起動したところ NOR の中身を壊し、復旧しました。

規則: 作り直したカーネルは、NOR の読み書きが純正と同じだと確かめるまで、NOR を書き込み可能でマウントさせない。次は NOR に触らない検証用の仕組みを先に作ります。
